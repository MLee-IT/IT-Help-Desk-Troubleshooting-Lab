# Troubleshooting Methodology

## Overview

This document outlines the general troubleshooting methodology used throughout the IT Help Desk Troubleshooting Lab.

The goal of the methodology is to approach technical issues in a structured and repeatable way while minimizing unnecessary changes and verifying the results of each troubleshooting action.

## 1. Identify the Problem

Begin by understanding exactly what the user is experiencing.

Questions may include:

- What is not working?
- When did the issue begin?
- Was the device or application working previously?
- Does the issue affect only one user or multiple users?
- Were any recent changes made?

## 2. Gather Information

Collect relevant information about the affected environment.

This may include:

- User
- Department
- Device
- Operating system
- Application
- Network connection
- Error messages
- Recent changes
- Frequency of the issue

## 3. Reproduce or Verify the Issue

When possible, confirm the reported problem directly.

Examples included:

- Attempting to open the affected application
- Testing network connectivity
- Checking a printer's status
- Reproducing an access error
- Reviewing system settings

## 4. Check Basic Causes First

Start with simple and common causes before moving to more advanced troubleshooting.

Examples:

- Power connections
- Network connectivity
- Cables
- Restarting the device
- Application status
- Available storage
- Account staus
- Basic configuration

## 5. Isolate the Cause

Use testing to determine which component or service is responsible for the problem.

For example:

- Test another network connection
- Test another device
- Check whether another user is affected
- Compare working and non-working configurations
- Review system logs
- Check device status

## 6. Apply the Appropriate Solution

Once a likely cause has been identified, apply the appropriate corrective action.

The solution should folloe oganizational procedures and avoid unnecessary changes to the user's system.

## 7. Verify the Resolution

Never assume an issue is resolved immediately after making a change.

Test the affected functionality again.

Examples:

- Open the application
- Access the network
- Print a test document
- Sign in to the account
- Access the shared resource
- Confirm the device is functioning normally

## 8. Document the Resolution

Record:

- What was found
- What caused the issue
- What action was taken
- How the issue was verified
- Any relevant technician notes

Clear documentation allows other technicians to understand what happened and what was done.

## 9. Escalate When Necessary

Not evert issue can be resolved at the help desk level.

Escalation may be suspected when:

- Hardware failure is suspected
- Administrative permissions are required
- A specialized team owns the affected system
- Security procedures require additional investigation
- Troubleshooting has been exhausted without resolution

When escalating, provide the next support team with the troubleshooting steps already completed and the findings collected.

## Core Principle

The overall approach is:

**Identify -> Gather Information -> Verify -> Isolate -> Resolve -> Verify -> Document -> Escalate When Necessary**

This process helps maintain consistent troubleshooting and provides a clear record of technical support activity.
